添加规则

一条规则里的所有域名、IP、进程（命中任意一个）都分到同一个去向。 规则从上到下依次匹配，上面的优先。

正则写法：域名栏用 re: 前缀（如 re:^.*\.cn$）； 进程栏直接写正则就行（含 ^ $ . * 等符号自动识别，如 ^/usr/lib/firefox/）。 语法按 Go RE2 —— 不支持前后向断言和反向引用，保存时会先校验。 IP 只能写 CIDR：sing-box 的 IP 匹配走前缀树，没有正则。 进程规则要流量先经过内核才生效 —— TUN 或系统代理都行； 不认系统代理的程序（Telegram、CLI 工具）得开 TUN 才会被进程规则捕获。

顺序即优先级（从上到下，首个匹配生效）。整体优先级： 端口直绑 → 模式开关 → 自定义规则 → 私有地址 → 默认走代理。

端口

网络

不做自动分流：主端口与 TUN 的流量全部走所选节点，私有地址与 .local 等内网域名直连。 需要某些流量直连时，加一个【直连】节点并把程序指向它的端口。

国内自动分流（可选）

默认关。开了之后这是最宽泛的一层「猜」，所以排在所有显式规则之后 —— 端口直绑、模式开关、「规则」页的自定义规则都优先于它。 IP 侧没有插全局 resolve：geoip-cn 匹配的是目标本来就是 IP 的连接。

TUN 全局代理

开启后所有程序都走代理，包括不认系统代理的 Telegram、CLI 工具。 需要内核具备 CAP_NET_ADMIN：执行一次 bash scripts/setup-tun.sh，之后启动免密码。

⚠ TUN 与 v2rayA / v2rayN / Clash 的全局模式不能同时开，会互相抢路由 —— 启动时会自动检测并拦住。

内核被强杀（断电 / OOM / kill -9）后可能留下指向已删网卡的策略路由，整机断网。 点上面的按钮清理本项目自己的残留（网卡 sbr-tun / 路由表 2023 / 规则段 9100）， 会弹一次系统授权框，其它客户端的 TUN 不受影响。等价于 sudo bash scripts/tun-recover.sh。

系统代理

这一项只影响图形程序（浏览器、桌面客户端）。命令行工具不读它 —— 看下面。

终端代理

curl / git / npm / pip / apt / docker build 完全不认上面那个系统代理，它们只看 http_proxy 这一类环境变量。「系统代理明明开着，终端里 git clone 还是卡死」 就是这么来的。

接管 = 往 ~/.bashrc / ~/.zshrc（用 fish 的话是 config.fish）里 挂一段带标记的 source，只对以后新开的终端生效。 已经开着的终端没救 —— 一个进程改不了另一个进程的环境变量，所以那边要粘一次上面那行命令。 动手之前会把原文备份到配置目录，取消接管时按标记整段摘掉，不碰你自己写的行。

生成的片段带活性检查：内核没在跑时不设变量。否则代理一停，每条 curl / apt 都会变成「连接被拒绝」，比没有代理更难查。 单个终端里可以用 proxyon / proxyoff / proxystatus 临时开关。
